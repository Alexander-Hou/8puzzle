# 8 数码问题 A* 算法求解程序 —— 需求分析文档

## 1. 项目背景与目标

8 数码问题（8-Puzzle Problem）是一个经典的图搜索问题。在一个 3×3 的棋盘上放置了 1 到 8 八个数字滑块和一个空格（用 `0` 表示）。玩家可以通过将空格与相邻的滑块交换位置来改变棋盘状态。

8 数码的可达状态总数为 9! / 2 = 181,440，任意状态的最长最短解为 31 步。这两个数字既是理论分析素材，也是"搜索规模不超过状态空间上界"这一验收标准的依据。

本项目的核心目标是：

1. **算法实现**：使用 **C 语言** 实现 A* 启发式搜索算法，寻找从任意合法初始状态到目标状态的最优解路径。
2. **策略对比**：通过控制变量法，在相同的初始状态和目标状态下，对比 **A* 算法（放错数码数 $h_1$）**、**A* 算法（曼哈顿距离 $h_2$）** 以及 **宽度优先搜索（BFS，$h=0$）** 三种搜索策略的性能表现。
3. **指标量化**：全面测量扩展节点数、生成节点数、内存相关指标、求解耗时等关键指标，量化评估启发式信息对搜索效率的影响。

## 2. 功能性需求（Functional Requirements）

### 2.1 命令行参数交互（CLI）

程序需要以命令行终端程序的形式运行，支持用户通过命令行参数指定输入和控制输出格式。

| 参数 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `-s, --start <string>` | 是（`--selftest` 与 `-b` 批量模式下除外） | 无 | 初始状态字符串，由 9 个以空格分隔的数字构成（如 `"1 2 3 4 0 6 7 5 8"`）。 |
| `-t, --target <string>` | 否 | `"1 2 3 4 5 6 7 8 0"` | 目标状态字符串，格式同 `-s`。 |
| `-m, --method <string>` | 否 | `h2` | 求解策略：`h1`、`h2`、`bfs`、`all`（见 2.4）。 |
| `-p, --print-path` | 否 | 关闭 | 打印从初始状态到目标状态的完整逐步移动过程及 3×3 棋盘矩阵；关闭时仅输出统计结果。 |
| `-r, --repeat <N>` | 否 | `1` | 将搜索重复 N 次，输出各数值指标的中位数与 `[最小值, 最大值]`，用于抑制毫秒级计时抖动。 |
| `-b, --benchmark <N>` | 否 | 关闭 | 批量基准模式：以固定随机种子生成 N 个可解初始状态，对每个初态依次运行三种策略并汇总输出。 |
| `--seed <uint32>` | 否 | 固定常量 | 批量模式的随机种子，保证同一 seed 输出完全可复现。 |
| `--csv <file>` | 否 | 无 | 将指标以 CSV 形式写入指定文件（格式见 3.1.1）。 |
| `--selftest` | 否 | 关闭 | 运行内建断言自检（见 5.1），不执行常规求解。 |
| `-h, --help` | 否 | 关闭 | 打印程序帮助说明与使用示例。 |

**输出约定**：`-m all` 与 `-p` 同时出现时，只打印 $h_2$ 策略的完整路径（作为最优解代表），另外两条策略仅输出指标，避免刷屏。`-b` 批量模式忽略 `-p`。

### 2.2 输入合法性校验

程序必须在启动搜索之前完成输入校验：

* 初始状态与目标状态均必须**恰好包含 9 个整数**；
* 每个整数必须落在 `0..8` 范围内；
* 9 个数字必须**恰好是 0 .. 8 的一个排列**（不重复、不缺失）。

任一条件不满足时，程序应打印明确的错误信息与正确用法提示，并以退出码 `1` 结束，**不得进入搜索**。逆序数判定在输入非法时无意义，因此校验必须先于可解性判定。

### 2.3 可解性预判（逆序数检查）

* **逆序数定义**：将棋盘按行优先展开为 9 个数字的序列，**忽略空格 `0`**，统计满足 $i < j$ 且 $a_i > a_j$ 的数对个数，记为 $\text{inv}$。
* 8 数码棋盘的宽度为 3（奇数），因此空格所在行不参与奇偶性判断：**初始状态与目标状态的逆序数奇偶性相同 ⇔ 问题可解**。
* **需求**：程序在启动任何搜索之前，必须先计算两者的逆序数奇偶性。若不一致，程序应**立即停止搜索**，输出明确的无解提示，并以退出码 `2` 结束，避免无效的内存与 CPU 消耗。
* 附带校验价值：任意可解实例的最短解长度一定不小于 $h_2(\text{start})$，该下界用于 5.1 的结果自检。

### 2.4 多估价函数设计

程序需支持并抽象出以下三种评估函数 $f(n) = g(n) + h(n)$：

1. **放错位置数码数（Misplaced Tiles, $h_1$）**：

$$h_1(n) = \sum_{i=1}^{8} \mathbb{I}(\text{pos}_{\text{current}}(i) \neq \text{pos}_{\text{target}}(i))$$

统计除了空格（`0`）外，当前棋盘与目标棋盘位置不匹配的数字个数。

2. **曼哈顿距离之和（Manhattan Distance, $h_2$）**：

$$h_2(n) = \sum_{i=1}^{8} (\vert{}x_{i, \text{current}} - x_{i, \text{target}}\vert{} + \vert{}y_{i, \text{current}} - y_{i, \text{target}}\vert{})$$

计算每个非零数字从当前网格坐标到目标网格坐标的横纵行列步数差之和。两张棋盘的数字到坐标映射均来自实际传入的状态与目标，不硬编码标准目标。

3. **宽度优先搜索（BFS, $h_0$）**：

$$h_0(n) = 0 \implies f(n) = g(n)$$

使启发评估失效，将 A* 退化为盲目逐层扩展的搜索，作为实验对比的基准。

**口径说明（重要）**：本实验中的 BFS 就是"$h \equiv 0$ 的 A*"。此时 $f \equiv g$，弹出顺序严格按层递增，等价于层序搜索；但同一层内的扩展顺序由确定性比较器决定，而非教科书队列 BFS 的先进先出。因此扩展/生成节点数与教科书 FIFO-BFS 不会逐一相同，三策略对比一律以本程序口径为准。

**理论性质**：$h_1$、$h_2$ 对 8 数码均满足**可采纳性**（$h(n) \le h^*(n)$）与**一致性**（$|h(n) - h(n')| \le c(n,n') \le 1$），因此三种策略都能求得最优解，且搜索过程中关闭（closed）的节点无需重新打开。

### 2.5 求解过程回溯与展示

当算法成功搜索到目标状态后，程序需通过节点数据结构中的父节点指针（`parent`），逆向回溯至初始状态，并顺推展示解路径：

* **逐步动作记录**：清晰标注每一步移动了哪个数字滑块（如 `Step 1: Move 6 DOWN`）。
* **棋盘矩阵输出**：按 3×3 的二维格局可视化打印出每个步骤的棋盘状态。
* **打印控制**：仅当使用 `-p` 标志时全量展示完整移动步骤；`-m all` 下只展示 $h_2$ 的路径。
* **可自动化校验**：每个步骤的输出行以固定前缀 `Step ` 起始，便于 `tests/run_tests.sh` 统计实际打印的步数。

### 2.6 退出码约定

| 退出码 | 含义 |
| --- | --- |
| `0` | 求解成功 |
| `1` | 参数或输入非法（含缺少 `-s`、数字非法、用法错误） |
| `2` | 判定为无解 |
| `3` | 内存分配失败或达到节点数上限 |
| `4` | `--selftest` 断言失败 |

## 3. 非功能性需求与性能指标（Non-Functional Requirements）

### 3.1 实验性能测量指标

为保证三种策略可横向比较，所有指标采用**唯一定义**，不得在实现中另行解释：

| 指标名称 | 单位 | 定义与采集说明 |
| --- | --- | --- |
| **解路径长度（Path Length）** | 步 | 目标节点的 $g$ 值，即最少移动步数。 |
| **生成节点数（Generated）** | 个 | 每次由扩展产生的候选子节点计数，**包含被 `best_g` 比较丢弃的候选**；只计数不要求实际分配 `Node`，因此恒有 `generated >= total_alloc_nodes`。 |
| **扩展节点数（Expanded）** | 个 | 从堆中弹出、通过"已关闭 / 已过期"检查并真正展开邻接节点的节点数；被跳过或判定为目标的弹出不计数。 |
| **OPEN 表容量峰值（Peak Open）** | 个 | 搜索全过程中堆内元素数量的最大值，**含尚未弹出的过期条目**（因此反映真实堆内存占用）。 |
| **CLOSED 峰值（Peak Closed）** | 个 | 状态表中 `closed = true` 的条目数量峰值；由于关闭只增不减，等于 Expanded。 |
| **累计分配节点数（Total Alloc Nodes）** | 个 | 本次搜索实际从内存池分配的 `Node` 总数（含根节点与被保留的候选，不含被去重丢弃的候选），用于估算峰值内存上界。 |
| **执行耗时（Execution Time）** | 毫秒（ms） | 仅统计搜索主循环，使用 `clock_gettime(CLOCK_MONOTONIC)`；不含参数解析、路径打印、结果输出与内存释放。 |
| **相对 BFS 剪枝率（Pruning Rate）** | 百分比（%） | $1 - \frac{\text{generated}(\text{method})}{\text{generated}(\text{bfs})}$，仅在 `-m all` 与 `-b` 模式下有意义（基准取自同一起始状态）；理论上可能为负，负值表示该策略生成节点多于 BFS。 |

#### 3.1.1 CSV 输出格式

CSV 首行为固定表头，其余每行对应一次"初态 × 策略"的运行结果：

```
method,start,target,path_len,generated,expanded,peak_open,peak_closed,total_alloc_nodes,time_ms,pruning_rate
```

单策略模式输出 1 行（`pruning_rate` 留空），`-m all` 输出 3 行，`-b N` 输出 3N 行。`pruning_rate` 列写入的是**百分比数值**（如 `92.79` 表示 92.79%），与终端对比表一致。

**可复现性**：`time_ms` 是测量值，天然存在抖动；除该列外，其余列在同一 `--seed` 下必须逐字节一致。

### 3.2 重复测量要求

* 单策略模式支持 `-r N`：连续运行 N 次，对 `generated / expanded / peak_open / peak_closed / total_alloc_nodes / time_ms` 报告中位数与 `[最小值, 最大值]`；路径打印只取第一次运行的结果。
* `-b N` 批量模式通过多个不同初态聚合性能表现，默认不叠加重复测量。
* 计时抖动在毫秒量级，单次结果不作为结论依据。

### 3.3 内存管理与稳定性需求

1. **统一内存池（arena）**：所有 `Node` 由内存池按块（chunk）批量分配，搜索结束后调用一次 `pool_free_all` 整体释放。堆与状态表只持有 `Node*`，自身不负责 `free` 节点，从而彻底消除泄漏与重复释放（double free）。
2. **所有权唯一**：`Node` 的生命周期只由内存池管理；堆只持有指针并在弹出时移除；状态表只记录 `best_g`、规范节点指针与关闭标志。
3. **分配失败处理**：内存池与堆的扩容（`malloc` / `realloc`）必须检查返回值，失败时打印错误并以退出码 `3` 结束，不允许直接崩溃。
4. **搜索界限保护**：设置节点数上限（内部常量，默认 5,000,000）。超过上限说明实现异常，应打印提示并以退出码 `3` 结束，而不是继续消耗内存。
5. **状态去重效率**：状态表基于哈希实现，查找与插入平均 O(1)，用于避免重复遍历与死循环。

## 4. 实验预期结果验证标准

在相同且可解的初态与终态下，程序运行结果必须满足以下标准：

1. **路径最优性**：由于 $h_1$ 与 $h_2$ 均满足可采纳性且一致，三种策略（$h_1$、$h_2$、BFS）求得的**解路径长度必须完全相等**，且等于目标节点的 $g$ 值。
2. **路径合法性**：从初始状态顺次回放解路径后必须恰好到达目标状态，且每一步都是空格与相邻滑块的合法交换。
3. **节点展开规模趋势**：总体上预期

$$\text{generated}/\text{expanded}(\text{BFS}) \ge \text{generated}/\text{expanded}(h_1) \ge \text{generated}/\text{expanded}(h_2)$$

即启发式信息的质量越好，搜索规模越小。注意该关系是**"≥ 且总体呈此趋势"**，对简单初始状态（例如只差一两步）三者可能完全相等，不能宣称严格大于。

4. **剪枝效率**：$h_2$ 应表现出最高的剪枝率与最小的 OPEN 峰值，$h_1$ 次之，BFS 为基准。
5. **规模上界**：BFS 在任意可解初态下的关闭节点数不超过可达状态上界 181,440；累计分配节点数不超过节点数上限。
6. **可复现性**：同一 `--seed` 下批量模式的确定性列逐字节一致（`time_ms` 为测量值，不参与比较）。

## 5. 测试与验收

### 5.1 内建 `--selftest` 断言清单

`--selftest` 不接收 `-s`，内部运行以下断言并输出 `PASS` / `FAIL`，全部通过退出码 `0`，任一失败退出码 `4`：

1. 非法输入被拒绝：数字重复、缺失、越界、个数错误均判定为非法。
2. 可解性判定正确：给定已知可解与已知不可解用例，结果与理论一致。
3. 三策略路径长度相等。
4. 解路径可回放：逐步验证每步合法，终点等于目标。
5. 下界成立：`path_len >= h2(start)`。
6. 目标节点 h = 0。
7. 退化用例：初态等于目标时路径长度为 0 且不崩溃。

### 5.2 黑盒验收（`tests/run_tests.sh`）

1. `make` 构建成功并产出 `bin/puzzle`。
2. 固定可解样例：三策略路径长度一致。
3. 不可解样例：退出码为 `2`。
4. 非法输入：退出码为 `1`。
5. `-b 5 --seed <固定值> --csv <临时文件>`：CSV 表头正确且数据行数为 15。
6. `--selftest`：退出码为 `0`。
7. `-m all -p`：输出中只出现一条完整棋盘路径（$h_2$）。

### 5.3 验收标准

* 文档中不再存在"仅检查 CLOSED、生成时丢弃一切重复"的旧语义；
* 每处动态分配都有唯一所有权，退出前无泄漏；
* 同一 `--seed` 的批量输出可复现；
* BFS 规模不超过 181,440 状态上界。
